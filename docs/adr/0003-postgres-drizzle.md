# ADR-0003: PostgreSQL with Drizzle ORM

- **Status:** Accepted
- **Date:** 2026-11-15
- **Deciders:** Billleaf founding team

## Context

Billleaf stores relational, financial data (documents, lines, payments) needing transactions, constraints, row locks for numbering, and later Row-Level Security.

## Decision

Use **PostgreSQL 17** as the system of record and **Drizzle ORM** for schema, queries and migrations, in `packages/db`. Conventions: UUIDv7 ids, `snake_case`, timestamptz, integer minor-unit money, `workspace_id` on business tables. Migrations generated by Drizzle Kit, committed, forward-only, run by a one-off migrate job.

## Consequences

- SQL-first, fully typed queries; schema is TypeScript shared by api and worker.
- Lightweight runtime, works well with Better Auth's Drizzle adapter.
- Fewer batteries than Prisma (no built-in studio-grade tooling beyond Drizzle Studio); developers must be comfortable with SQL.
- Postgres features (RLS, `FOR UPDATE`, JSONB) are directly available.

## Alternatives considered

- **Prisma** — great DX, but heavier engine, weaker control over SQL and RLS patterns.
- **TypeORM / MikroORM** — decorator-heavy, less type-safe queries.
- **MySQL** — weaker fit for RLS and some Postgres features we plan to use.
